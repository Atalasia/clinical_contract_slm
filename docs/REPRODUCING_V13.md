# Reproducing the v0.13 paper

Run these commands from this release repository's root, after activating the
environment described in [README](../README.md). Commands marked **inference**
load local model weights and require a compatible GPU. None is run merely by
installing or importing the package.

The inference commands below describe a **fresh local rerun**, not replay of the
author's archived outputs using changed provenance. The label-identity report in
section 4 also supports existing paired-note outputs with their original
configuration and provenance. No source datasets or result artifacts are bundled.
Offline tests use invented fixtures; they are not numerical replication of the
full experiment.

## 3. Matched full-versus-compact experiment

First preview the local manifest binding, review it, then create a separate local
configuration. The helper validates upstream files/counts and preserves the
original bindings in provenance; it does not rewrite the released declaration.

```bash
python scripts/bind_local_artifacts.py compact
python scripts/bind_local_artifacts.py compact --write
python -m cpg2.slm_contract_ablation preflight \
  --config configs/slm_benchmark/e1_contract_ablation.v1.local.json
```

Preflight uses local tokenizers but does not generate responses. It counts the
exact rendered prompt with `add_special_tokens=True`, matching this experiment's
existing vLLM string-input behavior. This includes any extra beginning-of-sequence
token inserted by the tokenizer even when the template already contains one.
The prompt text, string inputs, sampling settings, and generation call are
unchanged; the correction is to accounting and validation, not generation.
The paired clinical-note experiment below deliberately uses a different,
unchanged policy (`add_special_tokens=False`).

**Inference:**

```bash
python -m cpg2.slm_contract_ablation run-panel \
  --config configs/slm_benchmark/e1_contract_ablation.v1.local.json
```

No separate vLLM server is needed. One model runs per process, with all four
conditions per model. The runner checks complete cells before reusing them and
aggregates after the full panel completes. Repeat the same command to resume;
do not change code, configuration, wrappers, or runtime midway through a run.
Incomplete/mismatched artifacts require investigation or a separate output root,
not overwriting or selecting only successful responses.

The corrected runner checks actual prompt-token counts against preflight and
the context budget, including when validating completed cells. Because its
source hash and preflight accounting have changed, it must not resume or
re-aggregate artifacts created by the earlier runner. Preserve those artifacts
and their original provenance. For a new run alongside them, pass the same fresh
`--output-root` to `preflight`, `run-panel`, and `aggregate`; do not edit old audit
hashes to make them pass. Existing aggregate files can still be displayed with
`report_compact_contract_ablation.py --input PATH`; that command formats saved
statistics and does not revalidate or recompute them from raw responses.
For a nondefault run root, also point the compact report's `--input` at that
root's `aggregate/results.json`, and pass the same root as `--input-root` to
`analyze_contract_sensitivity.py` with a separate fresh diagnostic `--output-root`.

Inference-free reporting after completion:

```bash
python -m cpg2.slm_contract_ablation aggregate \
  --config configs/slm_benchmark/e1_contract_ablation.v1.local.json
python scripts/report_compact_contract_ablation.py
python scripts/analyze_contract_sensitivity.py \
  --config configs/slm_benchmark/e1_contract_ablation.v1.local.json
```

The last command rechecks saved response/source hashes and reports conservative
marker removal, retained state labels, and abstention/consistency categories. It
does not generate, repair, or replace responses. The original full/compact
acceptance rules and all-request denominators remain fixed.
Unlike the note label-identity report below, this synthetic sensitivity command
requires the saved run's inference-source hashes to match the analysis workspace;
use the original source snapshot for original archived synthetic outputs.

## 4. Prepare and run paired clinical-note annotation checking

MIMIC access is required. Source audit and request preparation read clinical text
locally; they are not model inference. Keep logs and all outputs restricted.

```bash
python -m cpg2 slm-benchmark-audit-ext-notes \
  --dataset-root data/mimic-iii-ext-notes-1.0.0 \
  --output outputs/local_restricted/slm_benchmark_v2/inventory/ext_notes_dataset_audit.json
python scripts/bind_local_artifacts.py e3-source
python scripts/bind_local_artifacts.py e3-source --write
python -m cpg2 slm-benchmark-e3-prepare \
  --config configs/slm_benchmark/e3.ext_notes.v1.local.json \
  --output-requests outputs/local_restricted/slm_benchmark_v2/ext_notes_context/dataset/requests.jsonl \
  --output-manifest outputs/local_restricted/slm_benchmark_v2/ext_notes_context/dataset/manifest.json
python scripts/bind_local_artifacts.py e3-paired \
  --primary-config configs/slm_benchmark/e3.ext_notes.v1.local.json
python scripts/bind_local_artifacts.py e3-paired \
  --primary-config configs/slm_benchmark/e3.ext_notes.v1.local.json --write
python -m cpg2.slm_e3_contract preflight \
  --config configs/slm_benchmark/e3_contract_comparison.v1.local.json
```

Preparation must retain all 2,288 candidates, 150 notes, 130 admissions and 130
subjects. The expected shared context decisions are 1,903 complete notes and
385 target-centered windows of at most 2,500 characters. Do not silently change
windows, sampling, or counts to accommodate another environment.

**Inference:**

```bash
python -m cpg2.slm_e3_contract run-panel \
  --config configs/slm_benchmark/e3_contract_comparison.v1.local.json
```

The runner generates both conditions for each model, checkpoints 128 requests
per batch, verifies completed batches, and computes the aggregate. No separate
API server is needed. Prefix caching and implicit special-token insertion are
disabled in both arms. The 96-token budget is fixed, including for failed outputs.
The earlier E3 inference is not required for this paired follow-up.

After completion, re-aggregation is inference-free:

```bash
python -m cpg2.slm_e3_contract aggregate \
  --config configs/slm_benchmark/e3_contract_comparison.v1.local.json
```

The aggregate's `strict` and `fence_normalized` sections contain the two scoring
views. In each, `cells.<model>.<condition>.hierarchical_joint.exact_match` supplies
the Table II agreement. Paired changes, model contrasts, per-head metrics, and
subject-cluster intervals remain separate fields.

The baseline needs the locally verified source files and prepared labels, but no
model outputs or GPU:

```bash
python scripts/report_clinical_note_baseline.py \
  --config configs/slm_benchmark/e3_contract_comparison.v1.local.json
```

It reports the fixed detection=yes, encounter=yes, negation=no comparator using
the existing hierarchical scoring rule, plus per-head metrics. The paper's joint
baseline is 1,259/2,288, not the product of marginal label frequencies. This is an
in-sample descriptive comparator, not an independently trained model.

### Compare the two generated label triples (no inference)

The accuracy aggregate does not establish whether the two conditions produced
the same labels. Use the separate saved-response report for the Results B
label-identity diagnostic:

```bash
python scripts/report_clinical_note_label_identity.py \
  --config configs/slm_benchmark/e3_contract_comparison.v1.local.json \
  --manifest-id mg4_it_v1
```

The report pairs responses by request ID, removes only a whole-response Markdown
fence from the unenforced arm, and parses the enforced arm strictly. It compares
the complete `(detection, encounter, negation)` tuple, not correctness against
reference labels. All prepared requests remain in the denominator. A parse or
schema failure in either arm counts as nonmatching, even if both failed.
Schema-valid triples are compared literally, including `abstain`,
`not_applicable`, and `unsure`, even when the labels violate cross-field logical
rules. Matching labels establish identity, not correctness or usability. Logical
consistency and abstention diagnostics are reported separately; the secondary
`identity_among_both_valid` measure restricts both its numerator and denominator
to pairs that are logically valid in both arms.
Incomplete or runtime-failed cells are rejected as unfinished runs, not silently
excluded from the candidate set. The primary report fields are
`triple_identity.identical`, `triple_identity.n`, and
`triple_identity.proportion`.

For the paper's MedGemma 4B run, the reported target is **2,257/2,288 = 98.6%**
after rounding. This is a result to reproduce, not a value forced by the script
or established by its unit tests. Use another declared `--manifest-id` to compute
the same diagnostic for another model.

By default, the command reads the configuration's output root and writes
`diagnostics/clinical_note_label_identity_<manifest_id>.json` beneath it. Only
aggregate counts, policies, and provenance hashes are exported; no note text,
request/cluster identifiers, or raw responses are exported. Outputs stay under
`outputs/local_restricted`; a different existing report is never overwritten.

For archived outputs, supply their **original** configuration and workspace:

```bash
python scripts/report_clinical_note_label_identity.py \
  --config /path/to/original/workspace/configs/slm_benchmark/e3_contract_comparison.v1.json \
  --repository-root /path/to/original/workspace \
  --run-root /path/to/original/workspace/outputs/local_restricted/slm_benchmark_v2/e3_contract_comparison_v1 \
  --manifest-id mg4_it_v1 \
  --output /path/to/original/workspace/outputs/local_restricted/label_identity_review/medgemma4.json
```

Replace the example workspace paths with your local paths. Do not bind archived
outputs to the portable release configuration. The command verifies saved
request, preflight, response, audit, and checkpoint consistency without loading
models/tokenizers or requiring the old inference environment. Recorded generation
source/runtime provenance is retained separately from the current analysis-source
hashes; this does not claim that the archived source implementation or model
weights were re-executed or independently verified.

After the two matched follow-up aggregates exist:

interaction renderer asserts the reported reversal pattern; the current renderer

## 7. Reproduction and privacy boundaries

The main matched analyses use 10,000 paired cluster-bootstrap resamples:
vignettes for synthetic requests and subjects for notes. Note requests remain
equally weighted. The matched intervals are exploratory and unadjusted; the
original synthetic interaction analysis separately reports its five-comparison
adjustment. No task scores are pooled into a composite leaderboard.

Local bindings are separate ignored `*.local.json` files, with original values
recorded under `local_binding`. Binding is preparation, not a way to relabel old
outputs. Stop on source, schema, count, runtime, or provenance mismatches. Rerun
into a new local root if a legitimate change creates a new experiment.

Keep source data, requests, outputs, checkpoint/log files and intermediate
statistics local. Do not upload them along with the code. Review even aggregate
exports before any redistribution. No end-to-end model inference or numerical
reproduction on clinical data was performed while preparing this release candidate.
